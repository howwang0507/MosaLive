# 0.3.6 本機體驗與診斷更新

本版整合長播穩定性、字幕閱讀、診斷與語言鎖定改善。既有翻譯快取 16 筆設定保留。

## 已完成

- 收音狀態：區分低音量、持續收音、長時間有聲音但未產生字幕、辨識原文及翻譯中。能量偵測不被當作人聲辨識，音樂可能屬有聲音但無字幕。
- 每分鐘統計：定稿句數、停句至定稿中位數/P95、丟棄音訊、恢復嘗試次數、字幕平均間隔。最近 60 個活動分鐘保留在記憶體，停止收音後隨 offscreen 關閉而消失。平均間隔包含自然停頓，無延遲資料顯示未知。
- 顯存每 15 秒抽樣，記錄各分鐘觀測最高值，並明確標示整張顯卡含遊戲等其他程式。不是 MosaSub 單獨顯存，也不是連續量測峰值。
- 最近 10 句供使用者選擇回報辨識／翻譯錯誤。只有主動回報才寫入 Chrome 本機儲存，最多 30 筆，可查看和一鍵清除；不存音訊、不上傳。
- 自動字幕停留：選「依字數自動」，2.5–8 秒；保留固定 2/3/5/8 秒及手動模式。新定稿仍即時替換舊句。
- 「只顯示定稿」選項減少暫定字幕跳動，代價是等待定稿才看到新句。
- 主播放器暫停 15 秒時提示，但仍監聽同分頁其他聲音；影片恢复或更換時取消舊暫停計時器。
- 面板檢查服務與版本，對比載入擴充套件版本及磁碟版本。此比較不能偵測同版本號的未重新載入修改。
- CHECK_ENV.bat 增加 CUDA 裝置查詢與埠/PID；CHECK_REAL_MODEL.bat 提供真正合成音訊辨識加翻譯請求。
- 每分鐘略過音訊新增原因拆分，分別顯示緩衝上限與播放重設，方便解釋長播丟棄量。
- 辨識模式分為自動多語與英文／日文／韓文鎖定。鎖定模式沿用既有請求值以維持協議相容，但後端改為將 `en`、`ja` 或 `ko` 直接傳入 Faster-Whisper，不再使用共用多語串流模型。

## 已做驗證

目前 JavaScript 40 項、Windows Python 32 項與其他 Python 9 項自動化檢查通過。新增自動停留上下限、分鐘統計上限、重複累計防護及語言鎖定標頭傳遞檢查。

英、日、韓鎖定模式另以專案既有合成語音進行真實 Faster-Whisper CUDA 抽測，三種模式均由 Faster-Whisper 回報指定語言。這項結果只證明語言參數與推論路徑生效，不是字元白名單，也不是直播準確率評分。

初次真實推論未通過，當時是舊後端啟動狀態為 ready，Ollama 沒有常駐模型。不能單以此證明失敗原因。重新啟動專案服務後真實測試成功：日文合成音訊辨識約 259.6ms，翻譯約 763.4ms；辨識設定回報 CUDA。此數字非真人準確率、非停句端到端延遲、非 GPU profiler 證據。

## 未完成的外部驗收

瀏覽器已看到自動停留選項；但後續 Chrome 控制連線逾時，再開 YouTube 時回報 browser unavailable。因此未完成 Twitch/YouTube/Bilibili 跨網站實播與全螢幕快捷鍵驗收，也未執行新版 30 分鐘壓力測試。不能據自動測試宣稱以上通過。

## 生效方式

本機後端已重啟並通過真實推論。Chrome 擴充套件仍需重新載入並重新整理影音分頁，再按「翻譯此分頁」。新的統計與回報位於擴充套件面板；自動停留和只顯示定稿位於字幕設定。
