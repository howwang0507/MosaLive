## 仍需完成

1. **0.3.6 真實驗收**：至少跑 30–60 分鐘 Twitch，記錄停句至定稿 P50/P95、首段中文、錯誤、恢復、丟棄音訊、RAM 與整卡顯存；測試時註記遊戲等其他負載。
2. **跨網站驗收**：Twitch 以外至少選兩個一般影音網站，測啟動、停止、切換、全螢幕、跳播與播放器重建。
3. **準確率基準**：英、日、韓各建立人工逐字稿，分開計算原文錯字與翻譯語意錯誤；專名、數字、否定與 `Chat` 類語境另列案例。
4. **公司模型介接規格**：需要模型位置或服務網址、輸入採樣率、語別、輸出是原文或中文、是否支援串流、硬體需求與授權。資料齊全後才可加入臺語、客語與族語路徑。
5. **交付方式**：Chrome Web Store 只能交付擴充套件；本機 Python、Ollama、CUDA 與模型仍需安裝器或公司服務。需決定競賽只展示開發版，或投入安裝封裝。

## 審查後優先序

### P0：把成果變成可信數據

- 增加測試前後 RAM、程序私有記憶體與後端 PID，避免把其他工具或遊戲算到 MosaSub。
- 分鐘統計已拆出播放重設與緩衝上限；後續再補傳輸失敗與手動停止的獨立計數。
- 儲存匿名化測試摘要，而非只看面板即時數字；不保存原始音訊。
- 以人工逐字稿做語言別基準，不能用單段合成音訊速度代表直播正確率。

### P1：改善第一次操作

- 面板用三步說明「啟動服務 → 選擇分頁 → 在來源分頁開始翻譯」。
- 偵測同頁多個正在播放的影音元素時明確警告混音。
- 啟動後顯示目前來源、偵測語言、模型狀態與最近一句完成時間。

### P2：準備競賽交付

- 填入團隊名稱，確認海地星空應用獎是否申請，再輸出最終 PDF。
- 準備固定展示網站、備援影片與一頁式操作卡，降低現場網路、廣告與直播內容不確定性。
- 把公司本土語言模型列為可介接資源，不宣稱已完成或已有品質數據。

## 必須重做或避免宣稱

- 不需重寫整個推論架構；目前分層、有限佇列、快取上限與恢復方向合理。
- 同一分頁的單一播放器隔離若是硬需求，必須改成逐一攔截媒體元素或平台專用整合，不能靠現有 tabCapture 達成。
- 目前不能宣稱支援所有網站、真人直播高準確率、長播無記憶體問題、臺客族語已完成，或顯存抽樣等於 MosaSub 自身用量。
