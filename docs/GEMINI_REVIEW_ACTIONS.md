# Gemini 建議核對與本機改善

本次依使用者要求排除語言模型相關變更，不推 GitHub。

## 已落實

- 快捷鍵 Alt+S：目前分頁開始／停止收音；Alt+C：清除；Alt+D：循環切換字幕。可在 Chrome 擴充功能快捷鍵頁改鍵，實際可用性仍取決於是否與其他程式衝突。
- 字幕設定新增文字描邊，搭配既有背景透明度 0 即為透明底字幕。
- 點擊穿透可在字幕設定啟用，在擴充套件面板解除；另提供可自行綁鍵的 toggle-through 指令。穿透時隱藏控制列，讓影片操作不被攔截。
- 主播放器辨識依序優先 Twitch、YouTube、Bilibili，再回退一般 video。這是選擇規則改善，不代表已通過這些網站的實播驗收，更不代表可繞過受保護影音。
- 面板加入術語讀取／編輯／儲存。每行「原詞 = 譯詞」，最多 100 組、每詞 60 字，保存在現有本機 glossary.json，沿用後端術語流程。使用者須先讀取再編輯，避免空白面板意外覆蓋現有詞庫。更新術語會使舊的句內翻譯重用結果失效。
- CHECK_ENV.bat：检查 Python 套件、Node 版本、NVIDIA 顯存、Ollama 及本機服務。已在本機執行；健康檢查只是服務可達與啟動狀態，不保證即時推論成功。

## 已有能力及必要修正

既有程式已有辨識排隊／耗時超過 800ms 時降低暫定辨識頻率、16 秒緩衝上限、失敗後有限次恢復。尚未用新版本實播證明能消除丟音訊，不能宣稱「徹底解決」。

30 分鐘紀錄中的 24.7 秒為丟棄音訊總量，當時指標不能區分播放重設與溢位，不能全部標為 Buffer Overflow。顯存上升也受同時遊戲影響。

## 未採用或需額外條件

| 建議 | 決定與原因 |
|---|---|
| 本土語言介接、模型分級、量化、FlashAttention、提示詞快取 | 本次排除模型相關變更。公司模型已有，不另找替代品。速度 2.5 倍、固定下降 200–400ms、100% 快取命中等數字沒有本專案對照證據。 |
| 靜音優先抽掉中間音訊 | 不直接做。現有 offset、commit_samples、重送資料與時間戳建立在連續採樣上；刪除中段靜音需建立原始／壓縮音訊時間映射。低音量也不等於沒有人聲，不能只用能量裁切。 |
| 積壓時加快 VAD 定稿 | 不直接做。可能把句子切斷並增加翻譯次數；先沿用降低暫定辨識頻率，並以實播衡量。 |
| 刪除 Node 橋接 | 可做但暫緩。server.mjs 還包含 /segment、串流翻譯整合、來源檢查、資料大小驗證與健康資訊；不是單純靜態託管。完整遷移需搬移接口與測試，不能只掛 StaticFiles 就刪除 Node，也未量測到橋接是主要瓶頸。 |
| Hami Video 展示 | 可規劃，尚不能宣稱串接完成。需確認實際可觀看內容、帳號、音訊擷取與展示條件；不能預先聲稱指定賽事沒有中文字幕。 |
| CHT 雲端／MOD／手機自動切換 | 目前沒有雲端端點、憑證、計費與設備端實作，不能只用提案包裝成已完成。音訊上雲也需明確告知使用者。 |
| 固定幻覺字句黑名單 | 不採一律刪除。「謝謝收看」可能是真話；既有置信度與重複性檢查更適合。需附人聲證據與測試音訊才能增加有條件規則。 |
| 毛玻璃及打字機效果 | 本次不加。毛玻璃增加畫面合成負擔，打字機會延後可讀內容；先以描邊、透明背景與穿透解決遮擋。 |
| 可攜式零安裝包 | 需乾淨 Windows 機器驗證驅動、套件、模型與發行條件。不能因本機可跑就稱零安裝；先交付檢查工具。 |
| 「專利級」術語功能 | 沒有專利或新穎性評估，不使用這項宣稱。 |

## 更新方式與驗收範圍

重啟本機服務，Chrome 重新載入擴充套件並重新整理影音頁。新增快捷鍵需確認瀏覽器是否成功註冊。既有前端 47 項測試通過，另新增字幕快捷控制及術語 API 拒絕無效輸入／外站來源測試。跨網站、全螢幕實際按鍵及修改後長播尚需真機驗收。
